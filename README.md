# Next Class — ระบบจัดตารางสอนอัตโนมัติ

ระบบจัดตารางสอนด้วย AI Agent สำหรับการแข่งขันทักษะเทคโนโลยีปัญญาประดิษฐ์ (ปวส.) ใช้ได้ 2 โหมด
- **โหมดเซิร์ฟเวอร์ (แนะนำ):** มีฐานข้อมูลกลางเก็บบัญชีผู้ใช้ ตารางสอน และข้อมูลทั้งหมด ดูหัวข้อ Backend ด้านล่าง
- **โหมดไฟล์เดียว:** เปิดไฟล์ `น้องไทม์ AI – ระบบจัดตารางสอนอัตโนมัติ.html` ได้ทันที ข้อมูลเก็บในเบราว์เซอร์เครื่องนั้น

## Backend (โฟลเดอร์ `backEnd/`)
ใช้ Node.js 22.5 ขึ้นไป ไม่ต้องติดตั้งแพ็กเกจเพิ่ม เพราะใช้ SQLite ที่มาในตัว (`node:sqlite`)

```
node backEnd/server.js                  # เปิดที่ http://localhost:3000  (หรือดับเบิลคลิก backEnd/start.cmd)
node backEnd/server.js --reset-admin    # ลืมรหัสแอดมิน → คืนเป็น admin/admin
PORT=8080 node backEnd/server.js        # เปลี่ยนพอร์ต · NC_DB=path เปลี่ยนที่เก็บฐานข้อมูล
```

ฐานข้อมูลอยู่ที่ `backEnd/data/nextclass.db` (SQLite ไฟล์เดียว คัดลอกไฟล์นี้ไปเพื่อสำรองข้อมูลได้)

| ตาราง | เก็บอะไร |
|---|---|
| `users` | บัญชีผู้ใช้ บทบาท (admin/teacher/student) การผูกกับครูหรือกลุ่มเรียน และรหัสผ่านที่แฮชด้วย **scrypt + salt** (ไม่เก็บรหัสจริง) |
| `sessions` | การเข้าสู่ระบบ เก็บเฉพาะค่า SHA-256 ของ token หมดอายุใน 7 วัน |
| `datasets` | ชุดข้อมูลที่นำเข้า (รายวิชา ครู ห้อง กลุ่ม นักเรียน คาบ และไฟล์ CSV ต้นฉบับ) เก็บทุกฉบับ |
| `timetables` | ตารางสอนทุกฉบับ: ที่มา, seed, ผลตรวจ Hard, Soft cost, ผู้สร้าง และย้อนกลับไปใช้ฉบับเก่าได้ |
| `timetable_entries` | ตารางรายคาบ (วัน คาบ วิชา กลุ่ม ครู ห้อง ทฤษฎี/ปฏิบัติ) query ตามกลุ่ม ครู หรือห้องได้ |
| `notes` | ข้อความ/แจ้งไม่ว่าง เช่น “ปิดปรับปรุงห้อง” แยกแบบห้ามจัดและแบบหมายเหตุ |
| `settings` | น้ำหนักเงื่อนไข Soft |
| `audit_log` | บันทึกการใช้งาน: เข้าสู่ระบบ, เข้าไม่สำเร็จ, บันทึกข้อมูล, จัด/แก้ตาราง, จัดการบัญชี |

**ความปลอดภัย**
- cookie แบบ HttpOnly และ SameSite=Strict และทุกคำขอที่แก้ข้อมูลต้องมี header ป้องกัน CSRF
- ถ้าเข้าสู่ระบบผิด 10 ครั้ง จะถูกล็อก 10 นาที
- บัญชีที่ใช้รหัสเริ่มต้นต้องเปลี่ยนรหัสเมื่อเข้าครั้งแรก
- สิทธิ์ตามบทบาท:
  - นักเรียนดูได้อย่างเดียว
  - ครูแก้ตารางและข้อความได้
  - แอดมินจัดการได้ทุกอย่าง
- เซิร์ฟเวอร์ปฏิเสธคาบเรียนที่อยู่ในคาบพักเที่ยง
- เซิร์ฟเวอร์ไม่ส่งไฟล์ในโฟลเดอร์ `backEnd/` หรือไฟล์ `.db` ออกทางเว็บ

**บัญชี:**
- ครั้งแรกเข้าด้วย `admin / admin` แล้วระบบจะบังคับให้ตั้งรหัสใหม่
- พอบันทึกชุดข้อมูล ระบบจะสร้างบัญชีครู (ใช้ teacher_id) และบัญชีนักเรียน/กลุ่มเรียน (ใช้รหัสนักเรียนหรือ group_id) ให้อัตโนมัติ รหัสเริ่มต้นคือ `1234`
- แอดมินจัดการบัญชี ดูประวัติตาราง และดูบันทึกการใช้งานได้ที่เมนูพิเศษ **ผู้ดูแลระบบ** (แท็บรูปโล่ เฉพาะแอดมิน)

## เริ่มใช้งาน (3 นาที)
1. เปิดไฟล์ HTML แล้วเข้าสู่ระบบด้วย `admin / admin`
2. ไปที่ **ข้อมูลและตรวจสอบ** แล้วเลือกไฟล์ 7 ไฟล์ของโจทย์ (หรือกดชุดตัวอย่าง “เล็ก”) → ตรวจพรีวิวกับผลตรวจ → กด **ยืนยันและบันทึก**
3. ไปที่ **จัดตาราง (AI)** แล้วกด **เริ่มจัดตาราง**
4. ไปที่ **ส่งออก/เผยแพร่** → `output.csv` ตามรูปแบบโจทย์, Excel, CSV, PDF

| บทบาท | ชื่อผู้ใช้ | รหัสผ่าน |
|---|---|---|
| แอดมิน | admin | admin (เปลี่ยนได้) |
| ครู | ชื่อครู หรือ teacher_id (เช่น T01) | 1234 |
| นักเรียน | รหัสนักเรียน / ชื่อกลุ่ม / group_id (เช่น G1) | 1234 |

## สิ่งที่ระบบรองรับ (เทียบเกณฑ์การให้คะแนน)
| เกณฑ์ | สิ่งที่ทำ |
|---|---|
| ไม่มีข้อขัดแย้งหลัก + หลักฐาน | ตรวจ Hard 10 ข้อ + เงื่อนไขชุดข้อมูล 8 ข้อ แสดงผล ✔/✖ พร้อมรายละเอียดทุกจุด |
| ครบตามเงื่อนไข 20 ข้อ | Hard 10 ข้อบังคับทุกครั้ง · Soft 10 ข้อวัดค่าได้และปรับน้ำหนักได้ |
| การตั้งค่า/ทดสอบซ้ำ | Seed + จำนวนรอบ + น้ำหนัก → ผลเหมือนเดิมทุกครั้ง (ใช้ PRNG mulberry32) |
| ผลลัพธ์/UI | ดูตามกลุ่ม/ครู/ห้อง/รายวิชา/รายวัน มีค้นหา เพิ่ม/ลบคาบ และแจ้งไม่ว่าง (เช่น ห้องปิดปรับปรุง) |
| ตัวชี้วัด | อัตราใช้ห้อง, คาบว่างนักเรียน/ครู, ภาระครูเฉลี่ย ± SD, Soft cost |
| ส่งออก | output.csv, Excel ครบชุด, CSV, PDF (ทุกกลุ่ม/ครู/ห้อง/รายวัน), JSON |
| UX ระหว่างคำนวณ | แถบความคืบหน้า + log + ปุ่มยกเลิก (เก็บผลดีที่สุดที่ได้) |
| Input | CSV / Excel / JSON + แม่แบบ, ตรวจก่อนคำนวณพร้อมคำแนะนำ, พรีวิวก่อนบันทึก, ชุดตัวอย่างเล็ก-กลาง-ใหญ่ |
| AI | CSP + Most-Constrained-First + Multi-start + Simulated Annealing ทำงานแบบ Agent Plan → Act → Check → Improve |
| หลักฐานว่าดีกว่าวิธีพื้นฐาน | ตารางเทียบกับ Baseline First-Fit ทุกครั้งที่จัด |
| ผู้ช่วย | แชตบอท “น้องไทม์” ตอบวิธีใช้งาน |

## อัลกอริทึม
1. **Plan** วิเคราะห์ภาระครูและกลุ่ม แล้วหาทรัพยากรที่ตึงที่สุด จากนั้นแตกวิชาเป็นบล็อก (ทฤษฎีติดกันไม่เกิน 2 คาบ ปฏิบัติติดกันไม่เกิน 4 คาบ)
2. **Act** สร้างตารางแบบ greedy CSP: จัดบล็อกยาวและวิชาที่มีครูให้เลือกน้อยก่อน ทุกช่องที่ผิด Hard จะถูกตัดทิ้ง แล้วเลือกช่องที่ Soft cost เพิ่มน้อยที่สุด ถ้าวางไม่ได้จะแบ่งบล็อกแล้วลองใหม่ ทำซ้ำหลาย seed แล้วเลือกผลที่ดีที่สุด
3. **Check** ตรวจ Hard 10 ข้อ
4. **Improve** ใช้ Simulated Annealing ย้ายหรือสลับบล็อกโดยไม่ผิด Hard และซ่อมคาบที่ยังจัดไม่ลง
5. **Check** ตรวจซ้ำ และเทียบผลกับ baseline

คาบที่ 5 (12.00–13.00) เป็นพักเที่ยง ห้ามจัดวิชา และเรียนได้ไม่เกิน 10 คาบต่อวัน

## โครงสร้างไฟล์
```
Next Class – ระบบจัดตารางสอนอัตโนมัติ.html   หน้าเว็บหลัก
styles/app.css                 สไตล์ (โหมดสว่าง/มืดตามระบบ, พิมพ์ PDF)
assets/fonts/                  ฟอนต์ IBM Plex Sans Thai (ใช้ออฟไลน์ได้)
backEnd/server.js              Backend: API + เสิร์ฟหน้าเว็บ + SQLite
backEnd/start.cmd              ดับเบิลคลิกเพื่อเปิดเซิร์ฟเวอร์ (Windows)
backEnd/data/nextclass.db      ฐานข้อมูล (สร้างอัตโนมัติเมื่อรันครั้งแรก)
scripts/core/app.js            ค่าคงที่ สถานะ การบันทึก
scripts/core/api.js            เชื่อมต่อ backend (ซิงก์เฉพาะส่วนที่เปลี่ยน)
scripts/data/data.js           อ่านไฟล์ CSV/Excel/JSON, data cleansing, validation
scripts/data/samples.js        ชุดข้อมูลตัวอย่าง เล็ก/กลาง/ใหญ่
scripts/scheduler/scheduler.js อัลกอริทึมจัดตาราง + ตรวจเงื่อนไข + ตัวชี้วัด
scripts/views/views.js         หน้าจอทั้งหมด + ส่งออก
scripts/auth/auth.js           เข้าสู่ระบบ + แชตบอท
```

## คอลัมน์เสริม (ไม่บังคับ)

- `room.csv`: `capacity`, `type`
- `subject.csv`: `room_type`
- `student_group.csv`: `unavailable`

## Deploy
- **ออฟไลน์:** เปิดไฟล์ HTML ได้เลย (ส่งออก Excel ต้องต่ออินเทอร์เน็ตเพื่อโหลดไลบรารี SheetJS ครั้งแรก)
- **ออนไลน์:** อัปโหลดทั้งโฟลเดอร์ขึ้น GitHub Pages หรือ Netlify หรือเปิดเป็น Artifact บน claude.ai แล้วกด “เผยแพร่”
- ข้อมูลเก็บใน localStorage ของแต่ละเบราว์เซอร์ ใช้ไฟล์โปรเจกต์ `.json` สำรองหรือย้ายเครื่องได้
